# Git vs SVN: сравнение

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто **указатель на коммит** (файл размером 41 байт с хешем).
Создание ветки не копирует файлы, а лишь добавляет ссылку. Переключение между
ветками — мгновенное, потому что вся история хранится локально.

В SVN ветка — это **физическая копия директории** в репозитории на сервере
(через `svn copy`). Даже если SVN оптимизирует хранение, семантика — копирование.
Создание и переключение ветки требует обращения к серверу и может быть медленным
на больших проектах.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система: коммит уходит **напрямую на сервер**,
локально хранится только рабочая копия (без истории). Без сети коммит невозможен.
В Git коммит создаётся локально (у тебя полная копия репозитория), а синхронизация
с сервером (`push`) — отдельный шаг, который можно отложить.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Legacy-проекты** в госсекторе и банках, где уже развёрнута инфраструктура SVN
  и миграция дороже, чем поддержка.
- **Очень большие бинарные файлы** (графика, видео, CAD), которые плохо ложатся
  в Git без Git LFS.
- **Команды с жёстким централизованным контролем** (нужен единый сервер с
  granular-правами на отдельные директории — в SVN это из коробки, в Git — сложнее).
- **Простые проекты**, где не нужны ветки и распределённая работа, а важна
  простота администрирования.
